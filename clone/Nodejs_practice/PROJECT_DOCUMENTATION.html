1. System Overview

This project is a scalable, secure backend service developed using modern ES Module JavaScript. It implements complete CRUD operations for todos while establishing an enterprise-grade security perimeter around user management, session lifecycle, and real-time activity auditing.

Architecture Highlights: Strict single-active-session policy per user, bcrypt credential hashing, stateless JWT verification, automatic RBAC capability indexing, and embedded web-based database administration.

3. Project Architecture

Clean separation of concerns adhering to the Controller-Model-Route pattern:

backend/
├── controller/
│   ├── controller.js          # Handles todo business logic (fetch, create, update, delete)
│   └── user.js                # Auth, registration, session management, access listing, audit queries
├── database/
│   └── db.js                  # Centralized mongoose connection initialization
├── middleware/
│   ├── admin.js               # Enforces admin role and active logged-in session state
│   └── auth.js                # Validates JWT tokens and resolves user identities
├── models/
│   ├── access.js              # roles_based_access schema and role-to-activity definitions
│   ├── activity.js            # session_logs schema (tracks login, logout, and session durations)

│   └── user.js                # users schema (username, email, password, role)
├── routes/
│   ├── route.js               # Todo management routes
│   └── user.js                # User identity, authentication, access, and audit routes

└── package.json               # Manifest & scripts

5. Authentication & Role-Based Access Control

Security Policies

  • Password Encryption: All passwords pass through bcrypt.hash(password, 6) before hitting the database.
  • Single Login Rule: A user cannot log in from a second location while their current session is marked "Session in progress". They must log out first.
  • Active Admin Verification: Admin routes not only verify the JWT token role, but also query session_logs to ensure the administrator is actively logged in.
  • Self-Deletion Protection: Administrators are explicitly forbidden from deleting their own active accounts.

7. Database Administration (Mongo Express)

Mongo Express is accessible locally at http://localhost:8081. Multiple UI customizations have been applied:

  • Zero Whitespace Bloat: Stripped HTML template indentation and overridden white-space: pre-line so cells display compact rows without empty lines.
  • Line-by-Line can_perform: Permissions are rendered with white-space: pre-wrap !important so each item appears on its own numbered line.
  • Admin-First Sorting: Default collection view sorts by { role: 1, username: 1 } ensuring administrators are always positioned above regular users.
  • Optimized Column Widths: activity_logs and roles_based_access use generous horizontal spacing and monospace formatting for IDs.
  • Full Screen Width: Utilizes full viewport width without artificial 1170px container margins.
  • Manual Cursor Column Resizing (All Collections): Users can shrink or expand the size of any table column across all collections manually using the cursor. Includes interactive col-resize grips, real-time dragging guidelines, double-click auto-fit reset, "Reset Column Width" button, click-sort prevention, and persistent storage in localStorage.
  • Light & Dark Mode Toggle: Top navigation bar includes a toggle button allowing users to switch between Light Mode and a dark slate theme with full persistence in localStorage.

8. Setup & Running Instructions

1. Start Local MongoDB Server

mongod --dbpath /home/cdot/mongodb/data --logpath /home/cdot/mongodb/mongod.log --fork

2. Start the Backend API Server

cd /home/cdot/Desktop/clone/Nodejs_practice/backend
npm start

Server starts and listens at http://localhost:4001.

3. Start Mongo Express Admin UI

cd /home/cdot/Desktop/clone/Nodejs_practice/backend
npm run mongo-express

Access the dashboard at http://localhost:8081.

User is already logged in Prior session was not closed with logout. Issue POST /api/user/logout or update logoutTime in session_logs collection.
